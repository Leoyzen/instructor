# Parallel Response Streaming

Parallel streaming enables real-time extraction and streaming of multiple structured objects simultaneously. This advanced feature allows you to process multiple models concurrently as they're being generated, providing incremental updates for each parallel tool call—similar to how `Partial` mode enables streaming for single tool calls, but extended to handle multiple models at once.

!!! tips "Motivation"

    Parallel streaming is ideal for scenarios where you need to extract and display multiple different types of structured information in real-time. Instead of waiting for all tool calls to complete, you can stream results as they arrive, enabling progressive UI updates, early validation, and performance optimization by processing completed tasks while others are still generating.

## Understanding Parallel Streaming

### Core Concepts

**Parallel Tool Calls**: Instructor can call multiple functions simultaneously when using `Mode.PARALLEL_TOOLS`. Each function call represents a different model type that can be extracted from the same text.

**Streaming**: Instead of waiting for all parallel tool calls to complete, streaming delivers incremental updates for each tool call as they're being generated by the LLM.

**ParallelResult**: This is the primary data structure you'll work with during streaming. It contains both completed models and partial (in-progress) models at each point in the stream.

## Basic Usage

### Single Model Streaming

Let's start with a simple example extracting a single `User` model:

```python
from openai import OpenAI
from pydantic import BaseModel
import instructor
from instructor.dsl.parallel import OpenAIParallelBase

# Patch the OpenAI client
client = instructor.from_openai(OpenAI(), mode=instructor.Mode.PARALLEL_TOOLS)

class User(BaseModel):
    """User information model."""
    name: str
    age: int
    email: str

# Create parallel base with User model
parallel_base = OpenAIParallelBase(User)

# Stream the parallel tool calls
for result in client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=parallel_base,
    messages=[
        {
            "role": "user",
            "content": "Extract information about John Doe, who is 30 years old and works as a Software Engineer.",
        },
    ],
    stream=True,
    max_tokens=300,
):
    # Display completed models
    for tool_call_id, model in result.completed.items():
        print(f"✓ Completed: {model}")
    
    # Display partial models (in progress)
    for tool_call_id, model in result.partial.items():
        print(f"⏳ Streaming: {model}")
```

### Multiple Models Streaming

The true power of parallel streaming becomes apparent when extracting multiple different model types simultaneously:

```python
from pydantic import BaseModel, Field
from typing import Optional

class User(BaseModel):
    """User information model."""
    name: str
    age: int = Field(..., ge=0)
    email: Optional[str] = None
    role: str = "User"

class Task(BaseModel):
    """Task information model."""
    title: str
    status: str = Field(..., description="Task status: todo, in-progress, completed")
    description: Optional[str] = None
    priority: int = Field(default=1, ge=1, le=5)

class Product(BaseModel):
    """Product information model."""
    name: str
    price: float = Field(..., ge=0)
    category: str
    in_stock: bool = True

# Create parallel base with multiple models
parallel_base = OpenAIParallelBase(User, Task, Product)

# Track which models we've already displayed
completed_tool_calls = set()

for result in client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=parallel_base,
    messages=[
        {
            "role": "user",
            "content": (
                "Extract: User 'Alice' age 25, Software Developer; "
                "Task 'Complete API Documentation' status 'in-progress' priority 4; "
                "Product 'Wireless Mouse' price $29.99 category 'Electronics'"
            ),
        },
    ],
    stream=True,
    max_tokens=500,
):
    # Display newly completed models
    for tool_call_id, model in result.completed.items():
        if tool_call_id not in completed_tool_calls:
            model_type = type(model).__name__
            print(f"\n✓ Completed [{model_type}]:")
            print(f"  {model.model_dump_json(indent=4)}")
            completed_tool_calls.add(tool_call_id)
    
    # Show partial progress
    if result.partial:
        partial_summary = [
            f"{type(m).__name__}: {m}"
            for m in result.partial.values()
        ]
        if partial_summary:
            print(f"⏳ Streaming: {', '.join(partial_summary)}")
```

## Core Data Structures

### ParallelResult

The `ParallelResult` dataclass represents the state of parallel tool calls during streaming:

```python
@dataclass
class ParallelResult:
    """
    Represents the state of parallel tool calls during streaming.
    
    Attributes:
        completed: Dict mapping tool_call_id to fully completed BaseModel instances
        partial: Dict mapping tool_call_id to Partial[Model] instances still streaming
        tool_call_id: The tool_call_id that was updated in this iteration
    
    Methods:
        get_all_models(): Get all available models (completed + partial)
    """
    completed: dict[str, BaseModel]
    partial: dict[str, BaseModel]
    tool_call_id: str
    
    def get_all_models(self) -> list[BaseModel]:
        """Get all available models (completed + partial)."""
        return list(self.completed.values()) + list(self.partial.values())
```

**Key Attributes:**

- **`completed`**: Dictionary of tool_call_id to fully completed and validated BaseModel instances
- **`partial`**: Dictionary of tool_call_id to models that are still streaming (may be incomplete or partially validated)
- **`tool_call_id`**: The identifier of the tool call that triggered this update

### ToolCallDelta

The `ToolCallDelta` dataclass represents a streaming delta for a single tool call:

```python
@dataclass
class ToolCallDelta:
    """
    Represents a streaming delta for a single tool call.
    
    Attributes:
        id: The unique identifier for this tool call (may be None in early chunks)
        index: The index position of this tool call in the parallel set
        name: The tool/function name being called (may be None in early chunks)
        arguments: The portion of function arguments received in this chunk
    """
    id: Optional[str]
    index: int
    name: Optional[str]
    arguments: str
```

## Synchronous vs Asynchronous Usage

### Synchronous Streaming

The examples above demonstrate synchronous streaming, which is appropriate for most use cases:

```python
# Synchronous streaming
for result in client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=parallel_base,
    messages=[...],
    stream=True,
):
    # Process each result
    if result.completed:
        for model in result.completed.values():
            print(model)
```

### Asynchronous Streaming

For applications requiring high concurrency or handling multiple requests simultaneously:

```python
from openai import AsyncOpenAI
import asyncio

# Create async client
async_client = instructor.from_openai(AsyncOpenAI(), mode=instructor.Mode.PARALLEL_TOOLS)

parallel_base = OpenAIParallelBase(User, Task)

async def stream_parallel_data():
    """Async streaming example."""
    async for result in await async_client.chat.completions.create(
        model="gpt-4o-mini",
        response_model=parallel_base,
        messages=[
            {
                "role": "user",
                "content": "Extract: User 'Jessica' age 31, Task 'Deploy to production' status 'in-progress'",
            },
        ],
        stream=True,
        max_tokens=300,
    ):
        completed_count = len(result.completed)
        partial_count = len(result.partial)
        
        print(f"Completed: {completed_count}, Partial: {partial_count}")
        
        for tool_call_id, model in result.completed.items():
            print(f"  ✓ {type(model).__name__}: {model}")

# Run async streaming
asyncio.run(stream_parallel_data())
```

## Advanced Features

### Validation Context

You can pass a validation context to influence the validation process:

```python
# Define validation context
validation_context = {
    "min_age": 18,
    "max_age": 100,
    "allowed_statuses": ["todo", "in-progress", "completed"],
}

for result in client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=parallel_base,
    messages=[...],
    stream=True,
    validation_context=validation_context,
):
    # Models will be validated with the provided context
    for tool_call_id, model in result.completed.items():
        print(f"✓ Validated: {model}")
```

### Strict Mode

Strict mode affects how JSON parsing is handled:

```python
# Streaming with strict mode
for result in client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=parallel_base,
    messages=[...],
    stream=True,
    strict=True,  # Enable strict JSON parsing
):
    if result.completed:
        user = list(result.completed.values())[0]
        print(f"✓ Extracted (strict mode): {user}")
```

- **`strict=True`**: Enforces stricter JSON parsing rules
- **`strict=False`** (default): More lenient parsing, better for partial data

## Real-World Applications

### Progressive UI Updates

Parallel streaming is perfect for updating user interfaces progressively as data arrives:

```python
def render_ui_state(result: ParallelResult) -> None:
    """Simulate progressive UI updates."""
    ui_state = {
        "user_card": False,
        "task_card": False,
        "product_card": False,
    }
    
    # Update UI components as models complete
    for tool_call_id, model in result.completed.items():
        model_type = type(model).__name__.lower()
        
        if f"{model_type}_card" in ui_state and not ui_state[f"{model_type}_card"]:
            ui_state[f"{model_type}_card"] = True
            
            # Simulate UI update
            print(f"\n🎨 UI Update: {model_type.upper()} card added!")
            print(f"   Data: {model}")
    
    # Show loading state for partial models
    if result.partial:
        loading = [type(m).__name__.lower() + "_card" for m in result.partial.values()]
        print(f"⏳ Loading components: {loading}")

for result in client.chat.completions.create(
    model="gpt-4o-mini",
    response_model=parallel_base,
    messages=[...],
    stream=True,
):
    render_ui_state(result)
```

## Best Practices

### 1. Track Completed Models

Always track which models you've already processed to avoid duplicate work:

```python
.completed_tool_calls = set()

for result in stream:
    for tool_call_id, model in result.completed.items():
        if tool_call_id not in completed_tool_calls:
            # Process the model only once
            process_model(model)
            completed_tool_calls.add(tool_call_id)
```

### 2. Handle Validation Errors

Implement proper error handling for validation failures:

```python
try:
    for result in stream:
        for tool_call_id, model in result.completed.items():
            # Re-validate for extra safety
            try:
                validated = type(model).model_validate(model.model_dump())
                use_model(validated)
            except Exception as e:
                print(f"Validation error: {e}")
                handle_error(model, e)
except Exception as e:
    print(f"Streaming error: {type(e).__name__}: {e}")
```

### 3. Rate Chunk Processing

For performance monitoring, track chunk reception rate:

```python
import time

chunk_count = 0
start_time = time.time()

for result in stream:
    chunk_count += 1
    
    # Log progress periodically
    if chunk_count % 10 == 0:
        elapsed = time.time() - start_time
        rate = chunk_count / elapsed
        print(f"Progress: {chunk_count} chunks received ({rate:.2f} chunks/sec)")

final_time = time.time() - start_time
print(f"Completed: {chunk_count} chunks in {final_time:.2f} seconds")
```

### 4. Use Type Checking

Leverage Python type hints for better IDE support:

```python
from typing import Dict, Set
from instructor.dsl.parallel import ParallelResult

def process_parallel_results(
    stream,
    expected_count: int = 3
) -> Dict[str, BaseModel]:
    """Process streaming results with type hints."""
    completed_models: Dict[str, BaseModel] = {}
    processed: Set[str] = set()
    
    for result in stream:
        for tool_call_id, model in result.completed.items():
            if tool_call_id not in processed:
                completed_models[tool_call_id] = model
                processed.add(tool_call_id)
        
        if len(processed) >= expected_count:
            break
    
    return completed_models
```

## Performance Considerations

### Memory Management

When processing large numbers of parallel models:

```python
# Process and discard models to reduce memory footprint
for result in stream:
    for tool_call_id, model in result.completed.items():
        # Process immediately
        process_and_save(model)
        # The model will be garbage collected after iteration
```

### Batch Processing

For high-volume scenarios, consider batching completed models:

```python
batch_size = 10
batch = []

for result in stream:
    batch.extend(result.completed.values())
    
    if len(batch) >= batch_size:
        # Process batch
        process_batch(batch)
        batch = []

# Process remaining items
if batch:
    process_batch(batch)
```

### Concurrent Processing

Combine parallel streaming with async for maximum throughput:

```python
async def process_concurrently(models: list[BaseModel]):
    """Process models concurrently."""
    tasks = [process_model_async(model) for model in models]
    await asyncio.gather(*tasks)

async for result in stream:
    if result.completed:
        await process_concurrently(list(result.completed.values()))
```

## Troubleshooting

### Issue: Missing tool_call_id

**Problem**: Early chunks may not have a tool_call_id yet.

**Solution**: The library automatically generates local IDs based on index. No action needed, but check result.tool_call_id for debugging:

```python
for result in stream:
    if result.tool_call_id:
        print(f"Update from: {result.tool_call_id}")
```

### Issue: Partial models fail validation

**Problem**: Partial JSON may fail validation.

**Solution**: This is expected behavior. Only trust models in `result.completed`, not `result.partial`:

```python
# Correct: Only use completed models
for model in result.completed.values():
    # Safe to use
    process(model)

# Incorrect: Avoid processing partial models
for model in result.partial.values():
    # May be incomplete or invalid
    process(model)  # ❌ Risky
```

### Issue: Unknown model name error

**Problem**: KeyError when model name not in registry.

**Solution**: Ensure all model types are registered:

```python
# Correct: All models registered
parallel_base = OpenAIParallelBase(User, Task, Product)

# Incorrect: Missing model
parallel_base = OpenAIParallelBase(User, Task)
# If LLM tries to extract Product, will raise KeyError
```

### Issue: Stream interruption

**Problem**: Stream ends unexpectedly.

**Solution**: Always handle the case where not all models complete:

```python
completed_models = []

try:
    for result in stream:
        completed_models.extend(result.completed.values())
except Exception as e:
    print(f"Stream interrupted: {e}")
    # Process whatever we got
    process_partial_results(completed_models)
```

## Comparison with Other Modes

| Feature | Parallel Streaming | Partial Streaming | Non-Streaming |
|---------|------------------|-------------------|---------------|
| Multiple Models | ✅ Yes | ❌ No | ✅ Yes |
| Real-time Updates | ✅ Yes | ✅ Yes | ❌ No |
| Partial Results | ✅ Yes | ✅ Yes | ❌ No |
| Completed Results | ✅ Yes | ❌ No | ✅ Yes |
| Use Case | Extract multiple structured objects in parallel | Show progress of single model | Get complete results at once |

**When to use Parallel Streaming:**

- Extracting multiple different types of information simultaneously
- Need to show real-time progress for multiple concurrent operations
- Want to start processing data as soon as it's available
- Building progressive UIs that update as data arrives

**When to use Partial Streaming:**

- Extracting a single complex model
- Showing field-by-field progress
- Minimal overhead needed

**When to use Non-Streaming:**

- Don't need real-time updates
- Simpler code is preferred
- All results needed at once

## Complete Example

Here's a comprehensive example demonstrating parallel streaming with all major features:

```python
from openai import OpenAI
from pydantic import BaseModel, Field
from typing import Optional
import instructor
from instructor.dsl.parallel import OpenAIParallelBase

# Initialize client
client = instructor.from_openai(OpenAI(), mode=instructor.Mode.PARALLEL_TOOLS)

# Define models
class User(BaseModel):
    name: str
    age: int = Field(..., ge=0, le=120)
    email: Optional[str] = None
    role: str

class Task(BaseModel):
    title: str
    status: str = Field(..., pattern="^(todo|in-progress|completed)$")
    description: Optional[str] = None
    priority: int = Field(default=1, ge=1, le=5)

class Product(BaseModel):
    name: str
    price: float = Field(..., ge=0)
    category: str
    in_stock: bool

# Create parallel base
parallel_base = OpenAIParallelBase(User, Task, Product)

# Define validation context
validation_context = {
    "min_age": 18,
    "allowed_roles": ["User", "Developer", "Manager", "Admin"],
    "allowed_categories": ["Electronics", "Office", "Accessories"],
}

# Streaming with comprehensive processing
completed_tool_calls = set()
processed_models = {"User": 0, "Task": 0, "Product": 0}

print("🚀 Starting parallel streaming extraction...\n")

try:
    for result in client.chat.completions.create(
        model="gpt-4o-mini",
        response_model=parallel_base,
        messages=[
            {
                "role": "system",
                "content": "You are a helpful assistant that extracts structured data accurately.",
            },
            {
                "role": "user",
                "content": (
                    "Please extract the following information:\n"
                    "User: 'Alex Johnson', age 28, email alex@company.com, role 'Developer'\n"
                    "Task: 'Implement user authentication', status 'in-progress', priority 5, "
                    "description 'Add OAuth2 support for Google and GitHub'\n"
                    "Product: 'USB-C Hub', price $45.99, category 'Electronics', in stock yes"
                ),
            },
        ],
        stream=True,
        max_tokens=500,
        validation_context=validation_context,
        strict=False,
    ):
        # Process newly completed models
        for tool_call_id, model in result.completed.items():
            if tool_call_id not in completed_tool_calls:
                model_type = type(model).__name__
                processed_models[model_type] += 1
                
                # Display model-specific results
                if model_type == "User":
                    print(f"👤 User extracted: {model.name} (age: {model.age}, role: {model.role})")
                elif model_type == "Task":
                    icon = "🔴" if model.status == "todo" else "🟡" if model.status == "in-progress" else "🟢"
                    print(f"{icon} Task extracted: {model.title} [{model.status}] (priority: {model.priority})")
                elif model_type == "Product":
                    stock_icon = "✅" if model.in_stock else "❌"
                    print(f"📦 Product extracted: {model.name} - ${model.price:.2f} ({stock_icon} {model.category})")
                
                completed_tool_calls.add(tool_call_id)
        
        # Show progress
        total_completed = sum(processed_models.values())
        total_partial = len(result.partial)
        
        if total_completed > 0 or total_partial > 0:
            print(f"   Progress: {total_completed} completed, {total_partial} streaming")
            # Show streaming models
            if result.partial:
                partial_types = [type(m).__name__ for m in result.partial.values()]
                print(f"   Streaming types: {', '.join(partial_types)}")

except Exception as e:
    print(f"\n❌ Error during streaming: {type(e).__name__}: {e}")
    print(f"Successfully extracted: {processed_models}")

# Summary
print("\n" + "=" * 50)
print("✓ Extraction Complete!")
print(f"Summary:")
print(f"  Users: {processed_models['User']}")
print(f"  Tasks: {processed_models['Task']}")
print(f"  Products: {processed_models['Product']}")
print("=" * 50)
```
